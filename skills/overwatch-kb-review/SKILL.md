# 守望先锋知识库复盘

像给玩家一起看录像的教练那样写。把播放条停在决策之前，讲清当时能看到什么、手里有什么、可以怎么做，再放到决策之后核对发生了什么。

## 取得本局事实

有 `overwatch-read-match` 的判读结果就直接接收片名、录像时间、回合目标、玩家、双方阵容和换人、团战、证据及来源。重点时刻有原片时回看动作前后。单独收到录像时可调用该技能；它不可用时，先从录像或关键帧自行确认同样几项再继续。按用户指定的英雄、时间窗或问题取材，只有 A 点片段就复盘到该片段结束。

按每波的准备、接战、转折、收尾寻找**真正有选择的一刻**。把动作前能看到的队友位置、敌人暴露的信息、地形、技能图标与大招读数记在该时刻。另记动作后的可见后果。回放全知视角、阵亡回放、队友后续报点或下一次充能只能解释后来发生的事。原始资料是文字或旧复盘时，照原来源措辞。

## 找到能解释这次选择的卡

1. **检索真实知识库。** 用户指定卡集时以该范围为准。在 overwatch-guide 项目中读取当前 `shared/knowledge.json` 及可访问的自建卡；单独运行且未指定库时，可直接读[随技能附带的项目知识库（12 张起始卡）](references/overwatch-guide-knowledge.json)。也能读取用户提供的 Markdown、JSON/JSONL 或检索工具返回的正文。沿用原卡 ID、标题、原始教学定位及更新日期等已有字段，没有 ID 时用真实标题和文件小节。
2. **围绕动作构造查询。** 组合“英雄/别名＋点位或团战阶段＋决策＋对方威胁”。例如温斯顿在国王大道 A 点要从二楼追人，可查“温斯顿/猩猩、二楼、追击、喷射背包/跳、回撤”，再按需要查“集火、辅助视线、人数交换”。精确查询未命中时，改查同英雄的通用卡、同职责卡或综合卡。写有专属地图或英雄的条目仍受各自适用范围约束，地图未确认时跳过依赖该点位的建议。
3. **按项目分类取材。** 从重装、输出、辅助三类查具体英雄，从综合类查瞄准、落位、交叉火力、技能交换、阵容和团战大招。同一片段可用多个分类。项目原库把“辅助”写作“支援”、“综合”写作“通用”，检索时按别名对应。版本资料负责英雄、地图和机制事实，引用时看发布日期、模式与录像版本；涉及精确数值或改动，使用相应日期的暴雪正式说明。给旧录像点评和给当前版本练习建议时分别标适用日期。[暴雪补丁说明](https://overwatch.blizzard.com/en-us/news/patch-notes/live/)
4. **按触发条件选卡。** 对齐角色、目标、敌方威胁、队友能否跟进、技能是否可用、退出条件。用最能解释这个动作的条目。两张卡分别提倡压前和后撤时，指出本局触发了哪一张的条件，必要时给条件分支。只影响数值的版本不确定性，可以略去数值，继续分析站位和时机。
5. **保留每句话的来处。** 读原卡的 `kind`。`教练笔记` 可引用所载原则，`官方机制` 用于解释英雄或规则，`观摩索引` 只指向值得对照的教学片段。引用教练原话须有实际原文或可定位的字幕。区分教练讲解、教学画面和蒸馏者推论。分别标“本局录像 01:20”和“教学来源 03:40”，即使两个时间相同也保留标签。卡里有标题、作者、链接、时间或章节就带上能定位的部分。没有命中的判断可以写成“画面判断”；用户要求只按知识库点评时，这类片段仅报告观察和缺失的教学依据。

## 把卡落到玩家当时的操作

| 复盘步骤 | 要回答的问题 |
| --- | --- |
| 决策前 | 争的目标是什么？我从哪进、打谁、谁能跟、还能从哪出？优先查玩家当时能见到的信号。 |
| 实际动作和结果 | 在具体秒数写“谁做了什么，随后谁丢了位置、被迫交技能、阵亡或获得目标进度”。把看见的结果与对原因的推断分开。 |
| 教学判断 | 画面符合卡里的哪条触发条件？下次值得保留的是哪一步，最早值得改变的是哪一步？同一失误的后果合并在这条点评里。 |
| 可执行的选择 | 写“看到什么信号 → 对谁或哪处使用哪个动作 → 走哪条退路/以什么情况结束”。在决定发生前核对技能、位置、控制状态和可用时间，解释这一改动带来的具体收益或代价。 |
| 按职责聚焦 | 重装看落点、争取的空间、技能为谁挡什么和撤退路线；输出看射线、目标与同步窗口；辅助看站位视线、保命或救人资源及受压时的退路。跨职责观点回到被复盘玩家能控制的那一步。 |

例如拆掉巴蒂斯特的维生力场，先查装置位置、攻击目标和装置消失的时刻，再判断是否给队友制造后续击杀机会。看到温斯顿阵亡，回到他仍能选择落点或走位的那一刻。团战赢了也能点评一次危险决策；团战输了也保留执行得好的那一步。

## 向玩家交付

- 先写本局最有价值的一条判断，随句给出录像时码。再按时间逐波讲；每波覆盖关键决策，重点给转折处。长局可用表，短片可用紧凑段落。
- 每条包含**本局时间和观察、知识卡及适用条件、下一次动作**。能核对时补实际后果。把教学来源放在点评末尾。用户要逐秒时，按指定区间报告变化，同一连续动作可合并并保留起止秒。
- 最后挑最影响目标、反复出现、玩家自己能改的动作作为练习。给出触发信号和下一局可以回看计数的指标，如“出现可选择的撤离窗口时，记录看见敌方起手到自己起跳的时刻”。分母用实际出现的有效机会；一个片段只出现一次就只评价这一次。
- 若仅有片段或部分知识卡，直接给出能成立的点评并在相关行标明缺口。文末检查每项技能建议在该时刻能否执行、录像时间能否定位、知识卡能否找回。接入复盘 Agent 时，每条点评携带真实的本局证据 ID 与命中卡 ID，保留画面观察、动作建议和教学出处三个字段；画面判断的卡 ID 列表可为空。项目卡的读取和已有案例见 [国王大道复盘示例](references/review-example.md)。
