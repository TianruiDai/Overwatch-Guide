# 证据、时效与版本核验

## 1. 来源优先级是两个问题

教学来源：按用户指定顺序检索；本项目先处理人上人老王，再按需补充 Guxue 等明确讲解的内容。没有实际字幕、音频或画面，不归因给作者。

规则事实：以与目标地区、模式、平台及生效日期一致的暴雪官方正文为证据。教学作者声望不能替代版本核验；官方规则也不能自动证明某一战术是最佳。

## 2. 官方入口

以下为导航入口，执行时需要打开并继续定位相关正文，而不是把入口 URL 当成具体事实的证据：

- 国际服补丁：<https://overwatch.blizzard.com/en-us/news/patch-notes/>
- 国际服英雄：<https://overwatch.blizzard.com/en-us/heroes/>
- 官方模式入口：<https://overwatch.blizzard.com/en-us/stadium/>
- 国服补丁：<https://ow.blizzard.cn/news/patch-notes/>
- 国服官网：<https://ow.blizzard.cn/>

官方域名默认白名单：overwatch.blizzard.com、ow.blizzard.cn；有直接来源链的暴雪官方论坛公告可以人工确认后纳入。域名白名单只是出处检查，不等于内容已被核验。

官网页面可能同时包含基础能力、模式专属能力和不同规则章节。读取正文时保留层级标题；同名能力的模式、数值和生效条件不能互相套用。

本文件是核验程序，不是任何日期的完整补丁快照，不预置当前英雄数量、威能数值或版本强度榜。

## 3. 核验步骤

1. 明确待核验命题，例如“某技能的冷却在某模式为某值”。
2. 明确目标规则：as_of、region、environment、mode、platform；缺失则注明。
3. 检查官方当前补丁入口和相关时间段的热修，定位命题所属章节。
4. 用相应英雄页/机制公告补足上下文；补丁没写某数值不等于该数值可凭记忆填入。
5. 若要确认当前数值，找到有效基线，并检查此后与该机制有关的改动；只读一个旧补丁，最多确认历史变化。
6. 核对发布时间与实际生效时间、地区是否同步、是否已回滚、是否仅适用于测试或特殊活动。
7. 记录具体页面、章节、检查时间、核验覆盖区间和无法确认的内容。
8. 生成 version 卡，再判断它影响哪些教学条件；不要从数字变动直接推断强度或胜率。

若页面打不开、仅有搜索摘要、正文未加载或来源之间冲突，标 unknown / conflict。不要把“未查到更新”写成“官方确认未更新”。

## 4. 两个时间轴和两个版本

- 视频时间轴：原文件播放器时间；游戏内时间、剪辑后的回放进度另记。
- 资料时间轴：录制时间、上传时间、补丁生效时间、核验时间。
- source_patch：教学对应的规则；未知时不从上传日期强行反推。
- target_patch：希望用于复盘或训练的规则；未完成核验时不填写一个猜测的补丁编号。

日期相近不代表规则相同。国服与国际服、5v5 与 6v6、常规与角斗领域、平台差异分别保留；无法消除差异时不要合并。

## 5. 陈述的四种性质

| basis | 允许的证据 | 不允许的升级 |
|---|---|---|
| source_statement | 实际字幕、语音、原作者正文 | 把模型建议写成作者原话 |
| observed_event | 实际视频、关键帧和可定位画面 | 从结果猜意图，从静态帧猜完整动作 |
| official_fact | 官方正文和明确章节 | 把第三方转述写成官网结论 |
| model_inference | 明示引用基础证据/已有陈述 | 冒充真实观测或已核验事实 |

对带字幕画面，可分别登记转录证据和视觉证据，但注明来自同一片段，不能当成两个独立来源提高可信度。

## 6. 状态

卡片状态：draft、ready、needs_review、archived、superseded、demo。

版本状态：not_checked、verified_for_scope、historical_only、conflict、unknown。

- ready：材料已核对且来源支持核心教学；不承诺跨版本有效。
- verified_for_scope：截至 checked_at，对明确 target_scope 有官方支撑；不是永久有效。
- historical_only：能确认历史语境，不宣称适用于当前。
- needs_review：关键观察不清、来源冲突、核心规则来自模型推广，或版本改变触及核心条件。
- demo：纯格式样例；禁止生产知识库检索。

数值敏感性：stable_principle、mechanic_dependent、numeric、mixed。stable_principle 只表示优先检查机制前提，不表示自动获得“永不失效”标签。

## 7. 更新与检索

新官方变化 → 找出 depends_on_cards 命中的教学卡 → 对受影响规则标记复核 → 保留原版本 → 创建修订并写变更原因。

新增证据但规则未变：追加证据，增加 revision。核心结论或适用范围改变：新修订；需保留前版，可用独立 ID 加 supersedes。

当前复盘检索顺序：按目标规则、英雄与地图过滤 → 排除 demo、冲突和已被替代内容 → 匹配条件、技能状态、对位 → 返回规则及证据 → 再对当前录像进行独立判断。

默认不将来源观点、旧版本规则或模型推论表述为“当前官方事实”。可在回答中作为限定范围的教学参考，但说明状态。

## 8. 引用与可追溯性

每个核心陈述绑定 evidence_ids，而不是只在整张卡末尾挂一个视频链接。每个 evidence 定位到具体时间段或正文章节。

记录作者、原始链接、短引文/转述和时间戳；仅摘录必要内容，不复制整段受版权保护的课程逐字稿。无字幕的视频在无音频读取工具时，只产出可支持的画面观察，不补造讲解。

文件哈希、关键帧路径、网页快照在真实可用时可附加；不写虚构的文件、URL 时间参数或截图引用。
