# 分类与切卡规则

## 五个目录，四类教学

| 一级分类 | 二级目录 | 典型内容 | 不应放入的内容 |
|---|---|---|---|
| tank / 重装 | 主体英雄 ID | 该重装的落位、进退场、技能循环、对位、威能、大招 | 只是被该重装攻击的辅助应如何反应 |
| damage / 输出 | 主体英雄 ID | 该输出的瞄准、枪线、爆发窗口、侧翼、联动 | 与具体英雄无关的鼠标控制通则 |
| support / 辅助 | 主体英雄 ID | 该辅助的治疗/输出分配、自保、资源与站位 | 只在画面中出现而没有讲解的辅助 |
| general / 综合 | 主题 | 通用瞄准、空间、资源、团战、大招经济、阵容、沟通、目标管理 | 仅有一个英雄案例、未经支持的普遍推广 |
| version / 版本 | hero / map / mechanic / mode / perk | 官方确认的身份、技能、数值、规则及改动记录 | 职业选手强度排名、胜率推断或“最佳选择” |

## 标签建议

标签用于检索，不增加主分类：

- 主题：aim、positioning、rotation、engage、disengage、cooldown、resource、ultimate、teamfight、composition、matchup、perk、objective、communication、training。
- 地图结构：high_ground、choke、corner、open_sightline、indoor、flank、environmental_hazard。
- 阶段：setup、poke、engage、midfight、cleanup、reset、overtime。
- 队伍职责：tank、damage、support；攻防方向：attack、defense、neutral。

使用稳定 ID 和可读中文名。未能确认的英雄或地图 ID 用 null，保留原始称呼到待核验队列；不要靠昵称、配音或玩家 ID 确认英雄。

## 主分类决策树

1. 这条内容是否陈述规则系统如何工作、数值或补丁变化？
   - 是：作为版本候选，查官方；核验完成生成版本卡，未完成留在待核验队列。
   - 若同时给出打法建议：再拆一张教学卡，关联版本事实。
2. 它主要要求某一位具体英雄的玩家改变动作吗？
   - 是：按该知识所述版本中的英雄职责分类，设置 primary_hero。
3. 它是否是跨角色协调、通用技能或同职业的一般原则？
   - 是：综合卡，用主题和职业标签组织。
4. 原材料是否足够确定上述答案？
   - 否：保留知识候选及歧义，不添加第六个知识类别，也不强行分类。

## 多卡拆分例（全部为结构示例，非真实教学摘录）

假设一段虚构字幕分别讲了：某重装如何进场，某辅助如何提前站到治疗角度，团队如何约定开团信号，以及某个技能刚被改动。

- 重装玩家自身的进场决策 → 重装／主体英雄。
- 辅助玩家自身的站位决策 → 辅助／主体英雄。
- 明确讲授的团队信号规则 → 综合／沟通与团战。
- 技能变化 → 待官方核验；取得官方事实后才生成版本卡。

这不是给同一句话复制四个标签。每一张卡必须有独立的决策内容和证据。

## 地图知识怎么归类

“某英雄从哪个位置进入、哪个位置撤退”属于该英雄教学；“所有角色转点时如何协调到达顺序”属于综合；“官方重做了某处地图结构”属于版本。

位置至少记录地图、阶段、攻防视角和地标。只说“左边二楼”而无参考朝向时，保留原称并标歧义，不能自行画成确定路线。

## 对位与多英雄

“英雄 A 如何对付 B”一般只生成 A 的教学卡。A 和 B 的玩家各有独立动作建议时，分别生成两张，并用 relations 或对位标签连接。

英雄协同以团队时机为核心，且没有单一主角时，归综合；同一讲解同时包含 A 的技能微操与团队时间安排时可以拆成英雄卡和综合卡。

## 卡片大小

可拆：进场前判断、单独的落点选择、不同条件下的退场、大招使用原则。

不必拆：一个技能连招不可分割的连续步骤；同一规则的两个等价示例；重复出现的同一错误。

判据：离开其他卡以后，这张卡能否独立回答一个实战问题？若不能，优先合并；若一张卡回答互不依赖的几个问题，优先拆分。

## 历史职业与当前目录

不硬编码当前英雄总数、职责名单或威能列表。建立必要的官方身份事实，记录 role_at_source 与 role_at_target。

旧版本的职业改变不意味着当年分类错误。历史卡按原规则保留；适配到目标版本后另建卡，并使用 supersedes / derived_from 关系连接。检索当前教学时过滤历史规则，而不是覆盖其来源。
